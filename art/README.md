# Mince Raft art

This folder holds the pixel art for Mince Raft: every block face, crop,
item, particle, sky sprite, inventory piece and creature skin. Each
texture is stored as text, with one character per pixel, all drawn from
one 16-colour palette. Text is easy to diff, review, generate with a
language model, and load in the engine without an image pipeline.

## What's here

| Path | What it is |
|---|---|
| `PROMPT.md` | The art brief: format, palette, style rules, model face conventions, and every batch's list of textures. It's the source of truth for what should exist. |
| `batches_1_6.json` | Batches 1–6: terrain, raft and workstations, crops, raw ingredients, dishes, tools and UI icons. |
| `batches_7_12.json` | Batches 7–12: remaining block faces, particles, sky, inventory, sea creatures, people. Generated by `tools/draw_7_12.py`; don't hand-edit it (see below). |
| `tools/draw_7_12.py` | The batch 7–12 drawings as Python data, plus small helpers for the sun, moon phases, digits and squid mottling. Run it to rewrite `batches_7_12.json`. |
| `tools/validate.py` | Checks every `batches_*.json`: palette, sizes, required model faces, duplicate names. |
| `tools/build_sheet.py` | Builds `build/sheet.html`, a preview page with every texture, tiling and animation previews, an inventory mock-up, and turning 3D model previews. |
| `tools/export_textures.py` | Writes the merged tileset the viewer loads. Owned by the viewer side; see the root `README.md`. |
| `build/` | Preview output. Gitignored. |

The preview page is also published as an artifact that anyone with the
link can open: <https://claude.ai/artifact/6YuKAFQsvqPBf7oykuuiN6>.

## Quick start

From this folder:

```sh
python3 tools/draw_7_12.py      # only if you changed the batch 7-12 drawings
python3 tools/validate.py       # must print "ok"
python3 tools/build_sheet.py    # writes build/sheet.html; open it in a browser
```

## How textures are stored

Each texture is a list of strings. Each string is one row of pixels, and
each character is a palette index:

```json
"bobber": ["........", "...0....", "..ccc...", "..ecc...",
           "..eee...", "..ee3...", "........", "........"]
```

- `0`–`9` and `a`–`f` are palette colours (the table is in `PROMPT.md`).
  `.` is transparent.
- Textures are 8×8 unless they're listed in the batch's `sizes`.
- Names are `snake_case`. Animation frames and growth stages end in `_0`,
  `_1`, and so on (`water_0`, `rice_3`, `puff_7`).
- Names are unique across all batches, because the engine looks textures
  up by name. The validator enforces this.

### Batch files

Each `batches_*.json` file maps batch labels to batches:

```json
{
  "Batch 9": {
    "title": "Sky",
    "tiles": false,
    "background": "night",
    "sizes": { "sun_sky": [16, 16] },
    "textures": { "sun_sky": ["...16 rows of 16..."] }
  }
}
```

| Key | Meaning |
|---|---|
| `title` | Section heading on the preview page. |
| `tiles` | `true` for block faces that must tile seamlessly. The preview's "Tile terrain 3×3" button repeats these. |
| `background` | Optional. `"night"` shows tiles on a dark sky colour, not the transparency checkerboard. |
| `sizes` | Optional. `{name: [width, height]}` for textures that aren't 8×8. |
| `textures` | `{name: rows}` for flat textures. |
| `models` | Used instead of `textures` for box models: `{model: {face: rows}}`. |
| `face_sizes` | Optional, for models. `{model: {face: [w, h]}}`. When it's present, the validator also checks that each model has exactly these faces. |

The preview page and validator pick up every `batches_*.json` file and
order them by the first number in the filename. A new batch can therefore
go in a new file, such as `batches_13.json`, without touching existing ones.

### Models

Fish, squid, the player and villagers are Minecraft-style box models.
Each box face is a separate small grid named `part_face` (`head_front`,
`body_left`, `arm_outer`). The orientation rules (which way each face
reads, where the creature's front is on a side face) are in "Model face
conventions" in `PROMPT.md`. Every new model must follow them, or its
faces won't line up when assembled.

Faces that are identical in every case are stored once and reused:
`tentacle_side` serves all four sides of every tentacle, and fish store
only `body_left`, which the engine mirrors for the right.

## Making new art

There are two ways to make a texture. Either works, as long as the
result passes the validator.

**With a language model.** Paste `PROMPT.md` and end with "Draw BATCH N
now." The model replies with one JSON object. Save it into a batch file
under a `"Batch N"` key and add the `title`, `tiles` and any `sizes`.
Then run the validator. Models often get row lengths wrong in big grids,
and the validator lists every row that's off.

**By hand.** Edit the rows directly in the batch file (or in
`tools/draw_7_12.py` for batches 7–12). Hand-drawing in a monospace
editor works well at this size. Check your work on the preview page,
which shows the texture at real colours, tiled and animated.

For either route:

1. Add the batch to `PROMPT.md` first, so the brief always matches what
   exists.
2. Save the textures, then run `tools/validate.py`.
3. Run `tools/build_sheet.py` and look at the page. For block faces, use
   "Tile terrain 3×3" to check the edges.
4. Run `./build.sh` from the repo root so the viewer gets the new
   textures. It runs `tools/export_textures.py`, which picks up every
   `batches_*.json` file and writes `viewer/textures.json`.

## Extending the art as mechanics are decided

Most new mechanics need a predictable set of art. Use these recipes, and
add each new batch to `PROMPT.md` in the same style as the existing ones.

### A new block

- Decide which faces differ. A block needs a `top`, `side` and `bottom`.
  Reuse an existing texture where it fits (the planter top could simply
  be `farmland_wet`).
- Name faces `<block>_top`, `<block>_side`, `<block>_bottom`, or just
  `<block>` if all faces match.
- Put opaque, tileable faces in a batch with `"tiles": true`.
- To show it in the viewer, add its tiles to `TILES` in
  `viewer/index.html` and map them in `tileFor()` (see the root README).

### A new crop

- Draw 3 or 4 growth stages, `<crop>_0` (just planted) to `<crop>_N`
  (ready to harvest). Each grows from the bottom row on a transparent
  background.
- Add the harvested item and its seed item to an item batch if they're
  new.
- Keep the stages visually related: the same stem colour and positions,
  getting taller and fuller.

### A new item or dish

- 8×8, transparent background, dark outline (`0` or `4`) around the
  silhouette, 2 to 6 colours.
- Dishes sit on the small white plate where it fits (see Batch 5).
- Check it in the inventory mock-up on the preview page. To show it
  there, add it to the `items` list in `inventoryMock()` in
  `tools/build_sheet.py`.

### An animated texture or particle

- Draw the frames as `<name>_0` to `<name>_N`. For looping block
  textures, each frame must tile, and the motion should wrap around (the
  water frames shift the same pattern by a fixed step).
- To preview the animation, add an entry to `SEQUENCES` in
  `tools/build_sheet.py`. It's keyed by the last frame's name and gives a
  label, the frame names, the milliseconds per frame, and whether it
  tiles.

### A new fish or sea creature

- Fish share one rig: a body box (W wide, H tall, D long), a flat tail
  plane and a flat dorsal plane. Choose a box size that fits the species
  (salmon 2×4×8, tuna 3×5×10, mackerel 2×3×7) and write a prompt entry
  like the existing fish in Batch 11.
- Add its `face_sizes` so the validator checks it.
- Add a rig entry to `RIGS` in `tools/build_sheet.py`. For a fish, that's
  one line: `name: f => ({ parts: fishRig(f, W, H, D), scale: 16 })`.
- Add the matching raw item (`raw_<fish>`) and any dishes made from it.

### A new villager variant

- Copy the `villager` face list from Batch 12 and change only the
  description: clothes, hair, colours. Keep the same face names and sizes
  so it reuses the villager rig.
- Name it `villager_<role>` and add a rig entry pointing at the villager
  rig: `villager_<role>: f => RIGS.villager(f)`.

### A new kind of model

- Write the box list first: each part's W×H×D and position. Then list its
  faces using the conventions in `PROMPT.md`.
- Add a rig function to `RIGS` in `tools/build_sheet.py`. A rig returns
  `{scale, parts}`, where each part is either
  `{box: [x, y, z, W, H, D], tex: {front, back, left, right, top, bottom}}`
  or a flat plane `{plane: [x, y, z], tex, w, h}`. The creature faces +z,
  and its left side is +x.

### Changing the palette

Avoid this if you can: every existing texture was drawn against the
current 16 colours. If the game needs a colour that's truly missing (for
example a dedicated skin tone), add it as a new index instead of changing
an existing one. Then update all of these together:

- the palette table in `PROMPT.md` (`export_textures.py` reads it from
  there);
- the `PAL` set in `tools/validate.py` and `tools/draw_7_12.py`;
- `PAL` and `NAMES` in `tools/build_sheet.py`.

### Redrawing a texture

Keep the name and size the same. The engine references textures by name,
so a redraw then needs no code changes. If you're replacing an
LLM-generated texture, edit the rows in its batch file directly. For
batches 7–12, edit `tools/draw_7_12.py` and rerun it.

## Decisions so far

These were settled while building batches 1–12. Revisit them as the game
changes.

- **No block breaking, health or hunger.** Batch 6's `heart_*` and
  `hunger_*` icons are unused for now, and no crack textures exist.
- **Swimming fish work like Minecraft 1.13.** Fish are visible models in
  the water, and fishing uses a bobber and a wake trail (Batch 8).
- **The interface is just the inventory for now**: slots, a nine-slice
  panel and stack-count digits (Batch 10). No menus, buttons or font yet.
- **No weather.**
- **The sky is drawn in code except the sun and moon.** Clouds, stars and
  the sky gradient should be generated in code. The sun is `sun_sky` and
  the moon has 8 phases, all 16×16. Batch 6's `sun`, `moon` and `cloud`
  are 8×8 icons, not sky sprites.
- **Skin tones use the existing tans and browns** (`6`/`7`/`5` lighter,
  `5`/`6`/`4` darker).
- **The world generator only makes** stone, dirt, grass, sand, gravel
  and water, and all of them have textures. Bedrock, sandstone and ice
  are already swapped for stone, sand and water in `SPEC.md`.

## Not decided yet

- **Chest and torch blocks:** only needed if the raft has storage
  blocks, or nights are dark enough to need light.
- **Trees:** `log_side`, `log_top` and `leaves` exist, but the generator
  doesn't place trees.
- **Flowing water:** frames exist (`water_flow_0`–`3`), but nothing pours
  water yet.
- **More villager variants:** only the sushi customer exists.
- **Model polish:** the villager's folded arms aren't tilted the way the
  1.14 model's are, the squid's mottling is random noise, and the moon
  crescents are cut almost straight. Redraw when they matter.
